# 実装計画の作成

`grill-me` Skillを利用して設計内容の詳細な仕様と実装方針を詰めていきます。ユーザーの合意を得たのち、 `writing-plans`　Skillを利用してドキュメントとして出力します。

## 使用確認のための指針

- なぜこの変更が必要なのか
- 何を満たせば完成なのか
- ドメイン上、壊してはいけない制約は何か
- コンポーネント間の責務をどのように分けるか
- どのような振る舞いを検証できれば正しいと判断できるか

## 質問

ユーザーへ確認の選択肢を提示する時、選択肢の概要の説明だけでなく、トレードオフについて説明してください。

## 議論が完了したら

`writing-plans`　Skillを実行し、計画の内容をドキュメント化します。まだ実装に移っていけません。

## ドキュメントが完成したら

- 今回の議論において、重要な意思決定を行った場合や、トレードオフの判断を残しておいた方が良いと判断したら、ユーザーに ADRを残すか確認してください。
- ユーザーがissuesを指定してる場合、該当issuesのコメントに、 `writing-plans` Skillsの内容をそのまま転記してください。
