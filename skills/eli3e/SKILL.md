このトピックについてドメイン知識のない人にもわかるように、アーキテクチャ図やデータフロー図などを用いてグラフィカルなHTML資料を使って説明してください。

技術用語を利用しても構いません。理解を助けようとし、技術用語や概念を日常生活に置き換える記述は返って理解の妨げや、誤った理解を誘発する可能性があります。

トピック: $ARGUMENTS

## 説明モードの選択

依頼内容に応じて、以下のモードを選択する。

### Concept mode

次のようなものを説明するときに使用する。

- 技術
- アーキテクチャ
- API
- ソースコード
- アルゴリズム
- インフラストラクチャ
- 設計パターン
- ライブラリやフレームワーク
- その他の技術概念

### Change mode

次のような変更内容を説明するときに使用する。

- Pull Request
- Git diff
- ローカルの未コミット変更
- PR作成前の実装変更
- 既存PRの変更内容
- コードレビュー対象の変更

コード変更をレビューするエンジニアが、
「何を、なぜ、どのように変更したのか」を短時間で理解できる資料を作成する。

対象には以下を含む。

- Pull Request
- PR作成前のローカル変更
- Git diff
- コミット
- 特定ブランチとの差分
