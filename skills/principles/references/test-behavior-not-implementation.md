# 実装ではなく振る舞いをテストする

テストは、使う側と同じ方法でコードを呼び、使う側が観測する結果をリテラルの期待値と比べる。コードがどんな呼び出しをしたかを検証するテストや、コード内の定数を書き写しただけのテストは、そのどちらもしていない。

確認方法: テストを残す前に、そのテストが import しているすべての関数が `undefined` を返しても通るかを問う。通るなら、そのテストは振る舞いを何も観測しておらず、欠陥があっても失敗できない。アサーションを書き直すか、テストを消す。

**理由:** 欠陥があっても失敗できないテストは、CI の時間とレビューの注意を消費するだけで何も捕まえない。定数を固定するテストは、誰かがその定数や、それが書き写しているプロンプトを編集したときにも失敗するので、正当な編集を妨げる。

**import した関数がすべて `undefined` を返しても通る 5 つの形**（例は Jest。pytest なら `assert x is not None`、`mock.assert_called()` などが同じ形に当たる）:

- **アサーションが弱いか、ない。** `expect` がない、または `toBeDefined`、`toBeTruthy`、`not.toThrow`、`toBeInstanceOf`、`toBeGreaterThan(0)` だけ。
- **モックか不在だけを見る。** `toHaveBeenCalled`、`not.toHaveBeenCalled`、`toBeUndefined`、`toEqual([])`、`toHaveLength(0)`、`not.toBe(wrongValue)` だけ。
- **自己参照。** 期待値がテスト対象のコードから来ている。`expect(f(a)).toBe(f(a))`、`expect(parsed.url).toBe(buildUrl(...))`。
- **定数の固定。** アサーションが、手で管理している定数、設定の既定値、テーブルの行、プロンプトの文字列を書き写している。`expect(LIMITS.maxTools).toBe(8)`、`expect(PROMPT).toContain("You are")`。
- **フィクスチャがフィクスチャを検証する。** アサーションが、テスト自身が作ったデータや `beforeEach` で計算した値を読んでいて、テスト本体の中でテスト対象が一度も実行されない。

**直し方:** テスト本体の中で、具体的な入力を 1 つ与えてテスト対象を呼び、リテラルの出力か観測できる効果を検証する。たとえば `expect(slugify("Hello, World!")).toBe("hello-world")` である。不在を検証するなら、同じテストの中で別の入力に対する存在も検証する。定数については、値を書き写すのではなく、その定数を読む仕組みを 1 つの入力でテストする。モックについては、呼ばれたことではなく、受け取ったペイロードか呼び出し後の状態を検証する。そのようなアサーションが存在しないなら、テストを消す。

**残してよいもの:** テーブルの行をまたぐ関係のテスト（2 つのテーブルに同じキーがある、親が存在する）と、`*.test-d.ts` ファイルのようなコンパイル時の型チェック。
