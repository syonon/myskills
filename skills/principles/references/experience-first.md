# 体験を優先する

実装の都合と使う人の満足がぶつかったら、満足を選ぶ。

- すべての機能、操作、オプションに存在理由が必要である
- 少なく、よく出す（荒い 10 機能より、磨かれた 3 機能のほうがよい）
- 確定する前に試作する（設計の判断は、本番コードより使い捨ての HTML で試すほうが安い）
- 細部を正しくする（遷移、揃え、余白、フィードバック、エラー状態）
- 中心の流れを引き締める（すべての機能は中心のワークフローに役立つか、邪魔にならない位置に置く）

使う人とは、成果物を利用する人である。UI なら最終ユーザー、ライブラリや内部 API ならそれを import する同僚である。次にコードを保守するエンジニアも使う人に含まれる。その人たちの体験も同じように重んじ、影響はその人たちの視点で説明する。

土台は体験に奉仕する。[土台から考える](foundational-thinking.md) は作業の*順序*を決め、この原則は*目標*を決める。
