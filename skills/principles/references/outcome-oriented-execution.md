# 結果志向で進める

途中の状態を滑らかに保つことより、意図した、検証できる最終状態を優先する。

**理由:** 途中のすべての段階を完全に安定させようとすると、一時的な互換コードが生まれ、それが長く残る負債になりやすい。目標の構成に収束させ、明示した検証の区切りで正しさを証明する。

**基本ルール:**
- 移行中の安定より、最終状態の整合性を優先する
- 計画され、範囲が限られ、元に戻せるなら、途中で壊れてもよい

**歯止め:**
- 段階の区切りが明確な、計画的な書き直しや移行にだけ使う
- 一時的に壊れてよい箇所を宣言する
- 移行中も、実際に触っている箇所には信号の強い検査を残す
- 計画の完了時には、静的検査と実行時の検証をすべて通す
