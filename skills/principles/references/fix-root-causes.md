# 根本原因を直す

デバッグでは症状を直さない。すべての問題を根本原因までたどり、そこで直す。

**理由:** 症状の修正は積み重なる。回避策が増えるたびにシステムは理解しにくくなり、本当のバグは残る。根本原因の修正は最初こそ時間がかかるが、デバッグにかかる総時間を減らす。

**進め方:**
- まず再現する
- 根本原因に届くまで「なぜ」を問う
- ガードを足さない（クラッシュを黙らせるための null チェックは症状の修正である）
- 回避策を正当化するのに 1 段落のコメントが要るなら、コードが間違っている（コメントではなくコードを直す）
- その 1 か所だけでなくパターンを確かめる（同じパターンを grep し、すべて直す）
- 行き詰まったら計装する。推測しない（ログを足し、実際のエラーを読む）

**再起動後のバグは、コードより先に状態を疑う**

「再起動すると失敗する」ときは、まず永続化された古い状態を疑う。設定ファイル、キャッシュ、ロックファイル、シリアライズされた状態などである。状態ファイルを消して挙動が戻るなら、状態の検証を修正の優先事項にする。
