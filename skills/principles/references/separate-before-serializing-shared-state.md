# 直列化する前に分離する

並行する主体が可変の状態を共有しうるときは、まず同じ可変オブジェクトが本当に必要かを問う。必要でなければ共有をなくす。共有が本当に必要なら、ロックファイル、段階の直列化、排他的な所有といった構造で直列化を強制する。指示や規約は並行制御にならない。

**理由:** 共有状態への並行書き込みは競合状態を生む。競合状態は断続的で、再現しにくく、デバッグの費用が高い。

**進め方:**
1. **共有されている可変状態を特定する**（両方が読み書きするファイル、両方が push するブランチ、両方が定義し利用する API）。
2. **既定では、共有の書き込み先をなくす。** これらの主体に 1 つの正規のオブジェクトが必要なのか、それとも独立した事実を発行しているだけなのかを問う。主体ごとに所有するファイル、キー、ブランチ、状態ディレクトリを与え、読み取りや報告の境界でだけ統合する。2 つのワーカーが 1 つの `state.json` にそれぞれの `lastX` フィールドを書くのは、やはり共有の変更である。`indexer-state.json` と `metrics-state.json` に分ければ共有ではない。
3. **共有の書き込み先が 1 つであることが本当の不変条件である場合に限り、構造で直列化する**（ロックファイル、段階の直列化、単一の書き手、アトミックな compare-and-swap）。「ロックが必要だ」は既定の答えではなく、確かめるべき設計上の兆候として扱う。
